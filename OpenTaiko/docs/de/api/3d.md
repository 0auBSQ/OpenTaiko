# 3D-Engine: Rasterizer-Welt <span class="badge-exp">Experimentell</span>

Szenen, Modelle, Lichter, Kameras, Physik, Collider, Wegfindung, Partikel, Render-Targets und Terrain-Höhenkarten.

Die 3D-Engine ist experimentell. Geplant ist, die experimentelle Kennzeichnung mit Version 1.0 fallen zu lassen.

<div class="callout">
Jedes globale Objekt und jede Methode auf dieser Seite kann sich zwischen Versionen ohne Übergangsfrist ändern. Wenn Ihr Skin darauf aufbaut, testen Sie nach jedem Update erneut und geben Sie an, für welche Spielversion er gedacht ist.
</div>

Auf dieser Seite verwendete Konventionen:

- Positionen und Größen sind Welteinheiten; +Y zeigt nach oben. Objekt-, Textur-, Sprite-, Material- und Primitiv-IDs sind Ganzzahlen.
- Winkel sind in Grad, sofern eine Zeile nicht Bogenmaß angibt (Fahrzeugausrichtung und -neigung in der Physik, Raddrehung, Phase der Grasbewegung).
- `Clear`, `FillRect`, `DrawLine`, `SetFog`, `ObjSetPass`, `PsEmit` und `PsBurst` nehmen Farben von 0-255. Lichter, die Sonne, das Umgebungslicht, Materialien, Einfärbungen und `ObjSetColor` nehmen lineare Farben von 0-1.
- Drei Renderer teilen sich dieselben Szenendaten: der GPU-Rasterizer (Standard, wenn GLES-3.1-Compute-Shader verfügbar sind), der CPU-Rasterizer (Rückfall, oder erzwungen mit `SetMode("raster_cpu")`) und der Pathtracer (`SetMode("raytrace")`). Die anderen Renderer ignorieren Zeilen, die mit *nur GPU-Rasterizer* oder *nur Pathtracer* gekennzeichnet sind.

Der Raytracer und die Physikwelt haben eigene Seiten: [Raytracer-Welt](3d-raytrace.md) und [Physik](3d-physics.md).

## Szenen

### SCENE3D

<span class="badge-exp">Experimentell</span>

Fabrik für 3D-Szenen. Eine Szene ist ein Render-Target, das eine Kamera, persistente Objekte, Texturen, Sprites, Lichter und Partikelsysteme besitzt; Sie zeichnen sie wie eine 2D-Textur.

| Methode | Beschreibung |
| --- | --- |
| `SCENE3D:CreateScene(width, height)  -> scene` | Erzeugt eine Szene mit der angegebenen logischen Größe in Pixeln und gibt ihr Handle zurück. Das Spiel gibt die Szene frei, wenn es die Stage des Skripts abbaut. |

### Szenen-Handle

<span class="badge-exp">Experimentell</span>

<div class="callout warn">
Ablauf pro Frame: Hintergrund zeichnen (FillRect oder ClearTransparent), Kamera und Geometrie pro Frame aktualisieren, Render aufrufen, dann Upload, dann Draw. Render leert den Farbpuffer nicht; zeichnen Sie daher Himmel oder Hintergrund zuerst.
</div>

```lua
local scene, floor

function onStart()
    scene = SCENE3D:CreateScene(1280, 720)
    scene:SetLighting(true)
    scene:SetAmbient(0.4, 0.4, 0.46)
    scene:SetSun(0.3, 0.8, 0.5, 0.85, 0.82, 0.72)

    scene:RegisterTexture(1, pixels, 16, 16)          -- pixels: 1-basiertes Array von 0xRRGGBB-Ganzzahlen
    floor = scene:NewObject()
    scene:ObjAddQuadTex(floor, 0,0,0,  0,0,8,  8,0,8,  8,0,0,  1, 8, 8, 1.0)
    scene:ObjSetBounds(floor, 0, 0, 0, 8, 0, 8)
end

function draw()
    scene:SetCameraPosition(4, 3, -6)
    scene:SetCameraAngles(0, -20)
    scene:FillRect(0, 0, 1280, 720, 90, 140, 220, 255)
    scene:Render()
    scene:Upload()
    scene:Draw(0, 0)
end

function onDestroy()
    scene:Dispose()
end
```

Schlägt der GPU-Renderer beim Rendern fehl (zum Beispiel bei einem Shader, den der Treiber ablehnt), wechselt die Szene für den Rest ihrer Lebensdauer zum CPU-Rasterizer, und die Stage läuft weiter.

#### Texturen und Sprites

Eine Textur ist ein deckendes RGB-Bild, das Quads und Dreiecke per UV abtasten. Ein Sprite ist ein ARGB-Bild, das Billboard-Sprites, Sprite-Quads, Partikel, Grashalme und Terrain-Splat-Gewichte verwenden. Textur-IDs und Sprite-IDs sind getrennte Namensräume, und das Registrieren einer bereits existierenden ID ersetzt deren Pixel.

| Methode | Beschreibung |
| --- | --- |
| `scene:RegisterTexture(id, pixels, w, h)  -> nil` | Registriert eine Textur aus einem 1-basierten Lua-Array gepackter `0xRRGGBB`-Ganzzahlen (Zeilenreihenfolge, Ursprung oben links). Ein negativer Wert markiert ein transparentes (Cutout-)Texel. Bilder über 4.194.304 Pixel ignoriert die Szene. |
| `scene:RegisterTextureFromImage(id, tex)  -> nil` | Registriert eine Textur, indem die Pixel eines geladenen Textur-Handles zurückgelesen werden. Das Zurücklesen verwirft Alpha und greift einmal pro Aufruf auf die GPU zu, was für die Verwendung pro Frame zu langsam ist. |
| `scene:SetTextureFilter(id, mode)  -> nil` | Abtastfilter für eine Textur: `"nearest"` (Standard), `"linear"` oder `"mipmap"`. Nur GPU-Rasterizer. |
| `scene:UnregisterTexture(id)  -> nil` | Vergisst eine Textur, einschließlich ihres GPU-Uploads und jedes an die ID gebundenen Render-to-Texture-Targets. |
| `scene:SetSpriteRGBA(spriteId, pixels, w, h)  -> nil` | Registriert ein Sprite aus einem 1-basierten Lua-Array von ARGB-Ganzzahlen (`a << 24 | r << 16 | g << 8 | b`, Zeilenreihenfolge, Ursprung oben links). |
| `scene:RegisterSpriteFromTexture(spriteId, tex)  -> nil` | Registriert ein Sprite, indem die Pixel eines geladenen Textur-Handles zurückgelesen werden. Das Zurücklesen greift einmal pro Aufruf auf die GPU zu, was für die Verwendung pro Frame zu langsam ist. |
| `scene:MakeSoftCircle(spriteId, res, edge)  -> nil` | Erzeugt ein weißes rundes Sprite von `res` x `res` Pixeln, deckend in der Mitte und zum Rand hin auf null ausblendend; `edge` formt den Abfall (1 ist linear, 2-3 ein weiches Leuchten). |
| `scene:MakeCrystal(spriteId, res)  -> nil` | Erzeugt ein sechsarmiges weiß-blaues Schneeflocken-Sprite von `res` x `res` Pixeln. |
| `scene:SetSpriteFilter(spriteId, mode)  -> nil` | Abtastfilter für ein Sprite: `"nearest"` (Standard) oder `"linear"`. Direkt nach dem Registrieren aufrufen. Nur GPU-Rasterizer. |
| `scene:UnregisterSprite(spriteId)  -> nil` | Vergisst ein Sprite, einschließlich seines GPU-Uploads. |

Der Register-Aufruf eines Modells registriert dessen Materialien als Texturen mit IDs ab 4000 (glTF) und ab 6000 (OBJ); halten Sie daher Ihre eigenen Textur-IDs unter 4000, wenn eine Szene auch Modelle zeichnet.

#### Objekte

Ein Objekt ist eine persistente Gruppe von Primitiven. Alle Primitive in einem Objekt müssen von derselben Art sein (texturierte Quads, flache Quads, texturierte Dreiecke, Billboard-Sprites oder Sprite-Quads); rufen Sie ObjBegin auf, bevor Sie ein Objekt mit einer anderen Art neu befüllen. Objekt-IDs beginnen bei 1.

| Methode | Beschreibung |
| --- | --- |
| `scene:NewObject()  -> id` | Erzeugt ein leeres, sichtbares Objekt im deckenden Durchgang. |
| `scene:DeleteObject(id)  -> nil` | Entfernt ein Objekt und seine Geometrie. |
| `scene:ClearObjects()  -> nil` | Entfernt jedes Objekt und jedes Partikelsystem und verwirft die Render-Caches. Texturen, Sprites, Lichter und die Kamera bleiben erhalten; Objekt-IDs beginnen wieder bei 1. |
| `scene:ObjBegin(id)  -> nil` | Leert die Primitive eines Objekts, damit Sie es neu befüllen können. |
| `scene:ObjAddQuadTex(id, x0, y0, z0, x1, y1, z1, x2, y2, z2, x3, y3, z3, texId, uMax, vMax, shade)  -> nil` | Hängt ein texturiertes Quad an. Die Ecken werden auf die UVs (0, vMax), (uMax, vMax), (uMax, 0), (0, 0) abgebildet; `shade` (0-1) multipliziert das Texel und steuert die Sonne, wenn Beleuchtung aktiv ist. |
| `scene:ObjAddQuadFlat(id, x0, y0, z0, x1, y1, z1, x2, y2, z2, x3, y3, z3)  -> nil` | Hängt ein einfarbiges Quad an; Farbe und Alpha stammen aus ObjSetPass. |
| `scene:ObjAddTriTex(id, x0, y0, z0, u0, v0, x1, y1, z1, u1, v1, x2, y2, z2, u2, v2, texId, shade)  -> nil` | Hängt ein texturiertes Dreieck mit expliziten UVs an. Modell-Handles befüllen Objekte mit diesem Primitiv. |
| `scene:ObjAddSprite(id, x, y, z, w, h, spriteId, billboard, cutout)  -> nil` | Hängt ein Sprite-Quad der Weltgröße `w` x `h` an, dessen untere Mitte bei (x, y, z) liegt. `billboard`: 0 feste XY-Ebene, 1 zur Kamera gewandt, aber aufrecht, 2 immer zur Kamera gewandt, 3 flach auf dem Boden liegend und entlang der SetGroundSpriteLight-Richtung gestreckt. `cutout` ungleich null führt einen Alpha-Test durch und schreibt Tiefe (deckender Durchgang); 0 blendet per Alpha (Objekt in den transparenten Durchgang legen). |
| `scene:ObjAddSpriteQuad(id, x0, y0, z0, x1, y1, z1, x2, y2, z2, x3, y3, z3, spriteId, cutout)  -> nil` | Hängt ein Sprite auf einem expliziten Welt-Quad an (Ecken werden auf die UVs (0, 1), (1, 1), (1, 0), (0, 0) abgebildet); kein Billboard. |
| `scene:ObjSetTransform(id, m)  -> nil` | Setzt die Modellmatrix des Objekts aus einer Lua-Tabelle mit 16 Zahlen in Zeilenreihenfolge (Translation in m[4], m[8], m[12]); nil stellt die Identität wieder her. |
| `scene:ObjSetTransform16(id, m0, m1, m2, m3, m4, m5, m6, m7, m8, m9, m10, m11, m12, m13, m14, m15)  -> nil` | Wie ObjSetTransform mit 16 einzelnen Argumenten; verwenden Sie dies für Aktualisierungen pro Frame. |
| `scene:ObjClearTransform(id)  -> nil` | Stellt die Identitäts-Modellmatrix wieder her. |
| `scene:ObjSetBounds(id, minX, minY, minZ, maxX, maxY, maxZ)  -> nil` | Bounds im Weltraum für das Culling hinter der Kamera, SetRenderDistance und ObjSetNormal. |
| `scene:ObjSetNormal(id, nx, ny, nz)  -> nil` | Behandelt das Objekt als planare Gruppe, die in Richtung (nx, ny, nz) zeigt, und überspringt es, wenn die Kamera hinter dieser Ebene liegt (benötigt ObjSetBounds); 0, 0, 0 deaktiviert. |
| `scene:ObjSetVisible(id, v)  -> nil` | Zeigt oder verbirgt ein Objekt. |
| `scene:ObjSetPass(id, pass, r, g, b, a)  -> nil` | Render-Durchgang (0 deckend, von vorn nach hinten gezeichnet; 1 transparent, von hinten nach vorn gezeichnet) plus die Farbe flacher Quads (0-255) und das Alpha (0-255), das auf flache Quads und Sprites angewendet wird. |
| `scene:ObjSetTint(id, r, g, b)  -> nil` | Farbmultiplikation pro Kanal (0-1) für texturierte Flächen und Sprites; 1, 1, 1 = keine. |
| `scene:ObjSetColor(id, r, g, b)  -> nil` | Flache Albedo-Überschreibung (0-1), die die Textur- oder Materialfarbe vor der Beleuchtung ersetzt; r < 0 hebt sie auf. Nur GPU-Rasterizer. |
| `scene:ObjSetEmissive(id, r, g, b)  -> nil` | Emissive Addition (Farbe += Basis x rgb); Werte über 1 speisen das Bloom von SetDiorama. 0, 0, 0 = aus. Nur GPU-Rasterizer. |
| `scene:ObjSetLit(id, lit)  -> nil` | Ob Forward-Beleuchtung auf das Objekt wirkt (Standard true); false rendert es nur mit seinem gebackenen Schattierungswert. |
| `scene:ObjSetCastShadow(id, on)  -> nil` | Ob die Sprites des Objekts in die Sonnen-Shadow-Map werfen (Standard true). Nur GPU-Rasterizer. |
| `scene:ObjSetDepthBias(id, bias)  -> nil` | Tiefenversatz per Polygon-Offset: negativ zieht das Objekt zur Kamera (Decals auf einer koplanaren Fläche), positiv schiebt es weg; 0 = aus. Nur GPU-Rasterizer. |
| `scene:ObjSetOverlay(id, on)  -> nil` | Zeichnet das Objekt zuletzt über einen geleerten Tiefenpuffer, sodass es immer oben erscheint (Ego-Perspektive-Modelle). |
| `scene:ObjSetXray(id, alpha)  -> nil` | Zeichnet die Sprites des Objekts als Geist mit diesem Alpha (0-1) erneut, wo Weltgeometrie sie verdeckt; 0 = aus. Nur GPU-Rasterizer. |
| `scene:ObjSetMaterial(id, matId)  -> nil` | Material, das der Pathtracer für dieses Objekt verwendet (-1 = Standard). Nur Pathtracer. |
| `scene:ObjSetTerrainSplat(id, splatSpriteId, tex1, tex2, tex3, tex4, worldW, worldH, uvScale)  -> nil` | Mischt vier Ebenentexturen pro Pixel anhand eines ARGB-Gewichtungs-Sprites (siehe Splatmap-Handle); `worldW`/`worldH` sind die Weltabdeckung des Splats, `uvScale` die Texturwiederholungen pro Welteinheit. `splatSpriteId` < 0 deaktiviert. Nur GPU-Rasterizer. |

| `scene:GrassAdd(x, y, z, h, phase, shade)  -> nil` | Pflanzt einen Halm mit seinem Fuß bei (x, y, z), Welthöhe `h`, Bewegungsphase in Bogenmaß und Schattierung 0-1. |

#### Partikel

Ein Partikelsystem ist ein Pool zur Kamera gewandter Billboards. Emittieren Sie hinein, rufen Sie PsUpdate jeden Frame auf, und die Rasterizer zeichnen die lebenden Partikel im transparenten Durchgang. System-IDs beginnen bei 0; ClearObjects macht sie ungültig.

| Methode | Beschreibung |
| --- | --- |

#### Render-to-Texture-Ansichten

Diese rendern die Szene aus einer anderen Kamera erneut in eine registrierte Textur, die ein Quad dann nach Bildschirmposition abtastet (ObjSetScreenTex), um Spiegel, Wasserreflexionen, Portale und Monitore zu zeigen. | --- | --- |

| `scene:SetReflectionGpu(on)  -> nil` | Leitet RenderView und RenderViewReflect über einen GPU-Offscreen-Durchgang. Standardmäßig aus; dann rendert der CPU-Rasterizer die Ansichten. Schlägt der GPU-Durchgang fehl, fällt die Szene auf den CPU-Pfad zurück. |

| `scene:RenderViewReflect(texId, px, py, pz, nx, ny, nz, clr, clg, clb)  -> nil` | Rendert die planare Reflexion an der Ebene durch (px, py, pz) mit der Normalen (nx, ny, nz) in die Textur `texId`. Der GPU-Pfad schneidet Geometrie unterhalb der Ebene ab. |

| `scene:ObjSetFresnel(id, f0)  -> nil` | Schlick-Fresnel-Reflektivität pro Pixel für eine bildschirmtexturierte Fläche (etwa 0.04 für Wasser); negativ deaktiviert. Nur GPU-Rasterizer. |

## Modelle

### MODEL

<span class="badge-exp">Experimentell</span>

Lädt glTF/GLB-Dateien (geskinnt, animiert) und OBJ-Dateien (statisch) in posierbare Modell-Handles.

<div class="callout warn">
Pfade sind relativ zum Skriptverzeichnis; der Lader akzeptiert auch absolute Pfade. Der Lader parst jede glTF-Datei einmal pro Prozess und teilt sie zwischen Szenen und Stages, sodass die mit SetPartObject gesetzte Teilezuordnung bis ClearPartObjects oder PurgeCache bestehen bleibt. Die glTF-Unterstützung umfasst indizierte Dreiecksprimitive mit Positionen, einem UV-Satz, optionalen Joints und Gewichten, einem Skin, Knotenhierarchien, linearen TRS-Animationen, Material-Grundfarben und eingebetteten Grundfarbtexturen (auf 512 Pixel an der langen Seite verkleinert). Die OBJ-Unterstützung umfasst Positionen, Texturkoordinaten, Polygonflächen und diffuse Farben aus der .mtl-Datei; Bildtexturen überspringt der Lader.
</div>

| Methode | Beschreibung |
| --- | --- |
| `MODEL:Load(path)  -> model` | Lädt eine .glb-, .gltf- oder .obj-Datei und gibt ein Modell-Handle zurück, oder nil bei Fehlschlag. |
| `MODEL:PurgeCache()  -> nil` | Verwirft den prozessweiten glTF-Cache (beim Verlassen der Stage). Laden Sie danach jedes noch verwendete Modell neu. |

### Modell-Handle

<span class="badge-exp">Experimentell</span>

<div class="callout warn">
Rufen Sie Register einmal pro Szene auf, dann Pose jeden Frame, um die platzierten (und bei glTF geskinnten) Dreiecke in ein Szenenobjekt zu schreiben. Animationsindizes sind 0-basiert; -1 posiert die Bind-Pose. Pose begrenzt die Animationszeit auf den Clip; wiederholen Sie sie daher selbst mit Duration. Die Methoden unterhalb von Duration gibt es nur bei glTF; OBJ-Handles stellen Register, Pose, AnimCount (0), AnimName und Duration bereit.
</div>

```lua
local model, obj
local clip = 0

function onStart()
    model = MODEL:Load("models/lantern.glb")
    if model then
        model:Register(scene)
        obj = scene:NewObject()
    end
end

function draw()
    if model then
        local t = elapsed % model:Duration(clip)
        model:Pose(scene, obj, clip, t, x, y, z, yawDeg, 1.0)
    end
end

function onDestroy()
    MODEL:PurgeCache()
end
```

| Methode | Beschreibung |
| --- | --- |
| `model:Register(scene)  -> nil` | Registriert die Materialien und Texturen des Modells in einer Szene (einmal pro Szene). |
| `model:Pose(scene, objId, anim, time, x, y, z, yawDeg, scale)  -> nil` | Leert das Objekt `objId` und füllt es mit den Dreiecken des Modells bei Animation `anim` und `time` Sekunden, verschoben nach (x, y, z), um Y um `yawDeg` gedreht und gleichmäßig skaliert. |
| `model:AnimCount()  -> number` | Anzahl der Animationsclips (0 bei OBJ). |
| `model:AnimName(i)  -> string` | Name des Clips `i`, oder "" außerhalb des Bereichs. |
| `model:Duration(i)  -> number` | Dauer des Clips `i` in Sekunden, oder 0 außerhalb des Bereichs. |
| `model:PartCount()  -> number` | Anzahl der Teile (Primitiv-Instanzen). |
| `model:PartMaterial(part)  -> number` | Materialindex eines Teils (0-basiert), oder -1 außerhalb des Bereichs. |
| `model:MaterialCount()  -> number` | Anzahl der glTF-Materialien. |
| `model:MaterialName(mat)  -> string` | Name eines glTF-Materials, oder "" außerhalb des Bereichs. |
| `model:MaterialEmissive(mat)  -> r, g, b` | Der glTF-`emissiveFactor` des Materials, oder 0, 0, 0, wenn keiner. |
| `model:SetPartObject(part, objId)  -> nil` | Leitet die Dreiecke eines Teils bei Pose in ein eigenes Szenenobjekt, sodass dieses Teil eigene Transparenz-, Emissions- oder Spiegel-Flags tragen kann; -1 hebt die Zuordnung für dieses Teil auf. |
| `model:ClearPartObjects()  -> nil` | Verwirft alle Teilezuordnungen. Beim Entladen der Welt aufrufen, da die Modellinstanz geteilt wird und Objekt-IDs nach ClearObjects neu beginnen. |
| `model:GetBounds()  -> minX, minY, minZ, maxX, maxY, maxZ` | Bounds der Bind-Pose im Modellraum. |
| `model:BuildCollider(mc, x, y, z, yawDeg, scale)  -> nil` | Hängt die Bind-Pose-Dreiecke, mit der angegebenen Transformation platziert, an einen MeshCollider an. Eine negative Skalierung wirkt als ihr Betrag. |

## Höhenkarten

### HEIGHTMAP

<span class="badge-exp">Experimentell</span>

Lädt rohe 16-Bit-Höhenfelder und RGBA-Splat-Bilder für Terrain und baut ein ganzes Terrain in einem Aufruf.

<div class="callout warn">
Pfade sind relativ zum Skriptverzeichnis. Eine Höhenfelddatei enthält w x h vorzeichenlose 16-Bit-Little-Endian-Samples in Zeilenreihenfolge; ein Splat-Bild ist ein RGBA-PNG, dessen Kanäle R, G, B, A die Gewichte der Ebenen 1 bis 4 sind. Bei einem Lesefehler geben beide Lader einen flachen Rückfall zurück.
</div>

| Methode | Beschreibung |
| --- | --- |
| `HEIGHTMAP:Load(path, w, h)  -> heightfield` | Lädt ein Höhenfeld mit w x h Samples; gibt bei Fehler ein flaches Nullfeld zurück. |
| `HEIGHTMAP:LoadSplat(path)  -> splatmap` | Lädt ein Splat-Bild; gibt bei Fehler eine Karte zurück, die vollständig aus Ebene 1 besteht. Ein vollständig deckender Alphakanal bedeutet, dass die Karte keine Ebene 4 hat. |
| `HEIGHTMAP:BuildTerrain(scene, floorObj, world, hf, splat, w, h, minY, maxY, cellSize, tex1, tex2, tex3, tex4, grassDensity, grassClump)  -> number` | Erzeugt das Terrain in einem Aufruf: ein texturiertes Quad pro Zelle in `floorObj` (Sample (ix, iz) liegt bei Welt-x = ix x cellSize, z = iz x cellSize, y = minY + Sample x (maxY - minY); jede Ebenentextur wiederholt sich einmal pro Zelle), passende Kollisions-Quads plus unsichtbare Randwände in `world` (zwischen BeginStatic und EndStatic aufrufen) und Grashalme auf Ebene-1-Boden abseits steiler Hänge und des Kartenrands, wenn `grassDensity` > 0 (`grassClump` > 0 gruppiert sie in Flecken). Ohne Splat verwenden steile Zellen `tex2` und der Rest `tex1`. Gibt die Anzahl der gepflanzten Grashalme zurück. |

<span class="badge-exp">Experimentell</span>
