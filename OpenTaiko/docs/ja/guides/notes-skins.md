# 音符と判定のパックの追加

スキンは音符と判定文字の見た目を複数用意でき、プレイヤーは設定でその 1 つを選びます。それぞれの見た目がパックで、スキンの `Graphics/5_Game/` の下にある番号付きのフォルダです。音符パックには音符、連打、風船、ヒットエフェクト、そして風船と連打の吹き出しが入り、判定パックには判定文字が入ります。このガイドでは、フォルダ、各パックに含まれるシート、パックを記述する `Definition.json` ファイル、そしてパックにないものをゲームがどう補うかを説明します。

## 始める前に

- 自分のスキン ([スキンとテーマの追加](skins.md)を参照)。同梱スキン `System/Open-World Memories/` には、コピー元にできる太鼓の音符パックが 4 つ、ボンゴの音符パックが 1 つ、判定パックが 4 つあります。
- 透過付きの PNG ファイルを保存できる画像エディタ。
- スキンの音符のセルサイズ。レイアウト値 `Game_Notes_Size=` です (同梱スキンでは `195,195`)。このページの音符シートのセルはすべてこのサイズで、巨大音符のシートだけが例外です。

## ステップ 1: パックのフォルダを作る

ゲームは `Graphics/5_Game/` の下で 3 つのフォルダを探し、その中の番号付きサブフォルダをそれぞれ 1 つのパックとして番号順に扱います。

- `Notes Skin (Taiko)/`: 太鼓プレイヤー用の音符パック。
- `Notes Skin (Bongo)/`: ボンゴプレイヤー用の音符パック。
- `Judges Skin/`: 判定文字のパック。すべてのプレイヤーが使います。

各フォルダのパック `1` は既定のパックで、ほかのパックの基になります (ステップ 7)。フォルダの番号はパックの並び順を決めるだけで、設定には `Definition.json` の名前が表示されます。

```
Graphics/5_Game/
  Notes Skin (Taiko)/
    1/                  <- the default look, complete
      Definition.json
      Notes.png
      ...
    2/                  <- another look: only the files that differ
      Definition.json
      Notes.png
  Notes Skin (Bongo)/
    1/
  Judges Skin/
    1/
      Definition.json
      Judge.png
```

## ステップ 2: 太鼓の音符シートを描く

シートはアニメーションのフレームごとに 1 行を持ち (フレーム数はステップ 5 で設定します)、セルは下の順に横に並びます。

| ファイル | 内容 |
| --- | --- |
| `HitCircle.png` | 判定枠。セル 1 つ。 |
| `Notes.png` | ドン、カッ、大ドン、大カッ、KaDon、ADLib。 |
| `Rolls.png` | 小さい連打の頭、胴、尾、続いて大きい連打の頭、胴、尾。ゲームは胴のセルを連打の長さに合わせて引き伸ばします。 |
| `Balloons.png` | 風船 (セル 2 つ分の幅)、くす玉 (セル 2 つ分の幅)、続いて導火線連打の頭、胴、尾。ボンゴプレイヤーにもこの風船が表示されます。 |
| `ChipEffect.png` | 任意。叩いた音符が到達する位置に表示されるフラッシュで、列は `Notes.png` と同じ、1 行です。これがなければ、ゲームは音符そのものを光らせます。 |
| `Notes_Partner.png` | 任意。`Notes.png` の各列のパートナー用の見た目 (ステップ 6)。 |
| `Notes_Giant.png` | 任意。巨大なドン、カッ、KaDon、ADLib (ステップ 6)。 |
| `Preview.png` | 任意。設定がそのパックに表示する画像。これがなければ `Notes.png` を表示します。 |

パックにはヒットエフェクトと、風船と連打の吹き出しも入ります。

| ファイル | 内容 |
| --- | --- |
| `Hit/Explosion.png` | 判定枠の上に出る爆発。1 行に正方形のフレームが 7 つで、良の行、可の行、さらに任意で大音符の良の行と可の行が続きます。2 行だけの場合、大音符は最初の 2 行を使います。 |
| `Hit/Explosion_Big.png` | 大音符の上に追加で出る爆発。画像 1 枚で、両方の判定で描かれます。 |
| `Hit/FireWorks.png` | 飛んでいく大音符が後に残す火花。 |
| `Hit/Bomb.png` | 叩いた爆弾、または失敗した導火線連打の爆発。1 行に 7 フレーム。 |
| `Hit/Great/`、`Hit/Great_Big/`、`Hit/Good/`、`Hit/Good_Big/` | 任意のフレームフォルダ (`0.png` から `14.png`)。小さい音符または大音符で良 (`Great`) や可 (`Good`) が出たときにレーン上に描かれます。 |
| `Kusudama/` | くす玉の `Script.lua` と、`Kusudama_Number.png` を含むその画像。 |
| `Fuseroll/` | 導火線連打の吹き出し `Fuse.png` と、その数字 `Number_Fuse.png`。 |
| `Breaking.png` | 風船の吹き出しが割れる画像。同じ高さの画像 6 枚を縦に並べます。 |
| `Balloon.png` | 風船の吹き出し。 |
| `Roll.png` | 連打カウンターの吹き出し。アニメーションのフレームを横に並べます。 |

## ステップ 3: ボンゴの音符パックを描く

ボンゴのパックには、ボンゴプレイヤーで異なるものだけが入ります。

| ファイル | 内容 |
| --- | --- |
| `Notes.png` | 赤、黄、ピンク、拍手、ADLib。 |
| `Rolls.png` | 赤、ピンク、黄、拍手の連打。それぞれ頭、胴、尾。 |
| `HitCircle.png` | 任意。これがなければ、ボンゴプレイヤーには太鼓のパックの判定枠が表示されます。 |
| `ChipEffect.png`、`Notes_Partner.png` | 任意。列はこのパックの `Notes.png` と同じです。 |
| `Notes_Giant.png` | 任意。列はこのパックの `Notes.png` と同じです。 |
| `Preview.png` | 任意。 |

風船、ヒットエフェクト、吹き出しは常に選択中の太鼓のパックから取られます。

## ステップ 4: 判定パックを描く

判定パックには `Judge.png` が入ります。同じ高さの 5 行で、良、可、不可、ADLib、そして爆弾の Boom です。その `Definition.json` に必要なのは `Name` だけです。行を透明にするとその判定は表示されなくなります。同梱スキンの "(Without Good)" パックは良の行でこれを行っています。

## ステップ 5: Definition.json を書く

`Definition.json` はパックに名前を付け、そのシートを記述します。どのフィールドも任意で、このファイルのないパックはフォルダの番号を名前として表示し、下の既定値を使います。

```json
{
	"Name": { "strings": { "default": "Sky Spirits", "ja": "スカイスピリッツ" } },
	"Notes": {
		"Frames": 3,
		"Animation": [
			{ "FromCombo": 0, "Rows": [0] },
			{ "FromCombo": 50, "Rows": [1, 1, 0, 0], "RowsOnEntry": [0] },
			{ "FromCombo": 150, "Rows": [0, 1] },
			{ "FromCombo": 300, "Rows": [0, 2], "RowsOnEntry": [0, 1] }
		]
	},
	"Rolls": { "Frames": 3, "Animation": [] },
	"Balloons": { "Frames": 3, "Animation": [] },
	"FlyingNotesFrame": 1,
	"PartnerNotesScale": 1.4142,
	"GiantNotesScale": 2.0
}
```

| フィールド | 既定値 | 意味 |
| --- | --- | --- |
| `Name` | フォルダの番号 | 設定に表示される名前。言語コードごとに 1 つの文字列で、それ以外のすべての言語には `default` を使います。 |
| `Notes`、`Rolls`、`Balloons` | 1 フレーム、アニメーションなし | シートの行数 (`Frames`) とアニメーション (`Animation`)。`Notes` は `Notes_Partner.png` と `Notes_Giant.png` の行も決めます。 |
| `FlyingNotesFrame` | `0` | 叩いた後にゲージへ飛んでいく音符に使う `Notes.png` の行。 |
| `PartnerNotesScale` | 2 の平方根 | パックに `Notes_Partner.png` がないときの、小さいパートナー音符の拡大率 (ステップ 6)。 |
| `GiantNotesScale` | `2` | パックに `Notes_Giant.png` がないときの、巨大音符の拡大率 (ステップ 6)。 |

`Animation` は段階のリストです。ゲームは、プレイヤーのコンボが到達した段階のうち `FromCombo` が最も大きいものを使います。1 拍は 4 つの区間に分かれ、`Rows` は各区間で描く行を指定します。短いリストは繰り返されるため、`[0, 1]` は区間ごとに交互になり、`[0]` は止まったままです。`RowsOnEntry` は、コンボがその段階に到達してから約 3 分の 2 秒の間、`Rows` の代わりに使われます。段階がなければ、シートは最初の行を表示します。例の表はゲームが従来から使ってきたアニメーションで、設定のシンプルモードではすべてのシートが最初の行のままになります。

## ステップ 6: パートナー音符と巨大音符

パートナー音符はほとんどの場合そのままのサイズですが、小さい音符 (小さいドンやカッ、ADLib、爆弾、すべてのボンゴの音符) は大きい見た目になります。巨大音符はずっと大きく、ゆっくり揺れます。それぞれに任意のシートがあります。

- `Notes_Partner.png` は `Notes.png` と同じ列と同じ数の行を持ちます。小さいパートナー音符は自分の列のセルを使います。
- `Notes_Giant.png` は `Notes.png` と同じ数の行を持ちます。太鼓のパックでは列はドン、カッ、KaDon、ADLib です。巨大音符は元のサイズにかかわらず大きく見えるため、小さいドンと大ドンはどちらもドンのセルを使います。ボンゴのパックでは列は `Notes.png` と同じです。セルのサイズはシートの幅を列数で割ったものなので、巨大音符のセルは音符のセルより大きくできます。

これらのシートがなければ、ゲームは `Notes.png` から見た目を作ります。

| 音符 | パートナー (`Notes_Partner.png` なし) | 巨大 (`Notes_Giant.png` なし) |
| --- | --- | --- |
| 太鼓の小さいドンまたはカッ | 大ドンまたは大カッ | 大ドンまたは大カッを `GiantNotesScale` 倍 |
| そのほかの小さい音符 | 音符を `PartnerNotesScale` 倍 | 音符を `PartnerNotesScale` 倍し、さらに `GiantNotesScale` 倍 |
| 大ドン、大カッ、KaDon | 変化なし | 音符を `GiantNotesScale` 倍 |

パックに両方のシートがある場合でも、両方の拡大率を設定してください。そうすれば、パックをコピーしてシートを削除したスキン制作者も適切なサイズを得られます。拡大した音符は引き伸ばした画像なので、そのサイズで描いたセルよりぼやけて見えます。

<div class="callout warn">ゲームは Notes_Partner.png、Notes_Giant.png、ChipEffect.png を選択中のパックからのみ読み込みます。これらはそのパック自身の音符と一致している必要があるため、パック 1 のものが代わりに使われることはありません。</div>

## ステップ 7: 残りはパック 1 に補わせる

選択中のパックにファイルがないとき、ゲームは同じフォルダのパック 1 からそれを取ります。そのためパックには変更するものだけを入れられます。`Hit/Explosion.png` の 1 行を消すだけのパックには、`Definition.json` とその 1 ファイルだけが入ります。規則は次のとおりです。

- ゲームはファイルを 1 つずつ確認し、フォルダの中 (`Hit/Great/3.png`) も同様です。例外はくす玉で、自分の `Kusudama/` フォルダを持たないパックはパック 1 のフォルダ全体を使います。
- フォールバックが届くのはパック 1 だけです。パック 3 を変えたパックは、パック 3 のシートのコピーを自分で持つ必要があります。
- `Definition.json` はパック 1 から取られることはなく、ステップ 6 の 3 つのシートも同様です。
- ボンゴのパックはボンゴのパック 1 にフォールバックします。

## ステップ 8: パックを選ぶ

スキンの 3 つのフォルダのいずれかに 2 つ以上のパックがあると、設定のテーマページの最初に「音符スキン」セクションが表示され、そのフォルダの選択肢と、その下にパックのプレビューが出ます。ゲームは選んだパックをすぐに読み込み、その選択をスキンごとに `ThemeSettings.db3` に記録します。パックが 1 つだけなら選択肢は表示されず、ゲームはそのパックを使います。

Lua モジュールは `THEME:GetNotesSkinFile(kind, file)` で選択中のパックのファイルを読みます ([プレイヤーとプロフィール](../api/players.md)を参照)。同梱の選曲画面はこれを使ってリプレイリストの判定文字を描いています。

```lua
local file = THEME:GetNotesSkinFile("judges", "Judge.png")   -- "5_Game/Judges Skin/2/Judge.png", or ""
if file == "" then file = "5_Game/Judge.png" end              -- a skin without judges packs
```

## パックのないスキン

`Notes Skin (Taiko)/` フォルダのないスキンは、パックができる前のファイルをそのまま使います。`Notes.png` (判定枠、4 種類の音符、連打、風船)、`Swap.png` (KaDon)、`Adlib.png`、`Kusu.png`、`FuseRoll.png`、`ChipEffect.png`、`10_Effects/Hit/` フォルダ、そして `11_Balloon/` の風船のファイルです。`Notes Skin (Bongo)/` フォルダがなければボンゴの音符と連打は `Notes_Konga.png` から取られ、`Judges Skin/` フォルダがなければ判定は `5_Game/Judge.png` から取られます。これらのファイルにはパートナー用や巨大音符用のシートがないため、パートナー音符と巨大音符はステップ 6 の拡大した見た目を使います。

## トラブルシューティングと注意点

- 設定に選択肢が表示されない: フォルダにパックが 1 つしかないか、パックのフォルダ名が数字ではありません。
- パックに別のパックの音符が表示される: パックにファイルがないためフォールバックがパック 1 のファイルを取ったか、大文字と小文字を区別するシステムでファイル名の大文字小文字が違います。
- 音符のフレームが違う、または画像が切れて表示される: `Frames` がシートの高さをセルの高さで割った値と一致していません。
- コピーしたパックのパートナー音符や巨大音符が元のものと同じに見える: コピーに元のパックの `Notes_Partner.png` や `Notes_Giant.png` が残っています。
- ボンゴプレイヤーに音符が表示されない: 選択中のボンゴのパックとボンゴのパック 1 の両方に `Notes.png` がありません。
