# Как работают модули

OpenTaiko 0.6.1 позволяет скину добавлять и заменять экраны с помощью Lua. Папка Modules скина содержит по одной папке на модуль, и у каждого модуля есть Script.lua, который определяет фиксированный набор глобальных функций обратного вызова. Игра загружает каждый Script.lua в собственное изолированное состояние Lua, регистрирует глобальные объекты движка (TEXTURE, SOUND, INPUT, CONFIG и остальные, описанные в [справочнике API](api/README.md)) и вызывает обратные вызовы в нужные моменты. Точные сигнатуры перечислены на странице [Модули и жизненный цикл](api/activities.md).

## Прежде чем начать

- OpenTaiko 0.6.1 и папка скина с каталогом Modules. Поставляемый скин находится в System/Open-World Memories.
- Текстовый редактор и базовые знания Lua (функции, таблицы, require).
- Поставляемые сцены в System/Open-World Memories/Modules/Stages. Небольшие, demo1 и demo3, показывают форму обратных вызовов; крупные показывают, как устроены настоящие экраны.

## Где находятся модули

У каждого вида модулей есть своя папка внутри Modules, и каждый модуль представляет собой одну папку, имя которой является идентификатором модуля:

```
Modules/
  Stages/        <name>/Script.lua   полноценные экраны
  Activities/    <name>/Script.lua   подэкраны, управляемые сценой
  ROActivities/  <name>/Script.lua   подэкраны и наложения только для чтения
  Transitions/   <name>/Script.lua   переходы между сценами (загружаются первыми)
  Lib/           общие .lua-файлы, доступные через require; как модули не сканируются
```

Точкой входа всегда является Script.lua. Пути к ресурсам, которые вы передаёте в TEXTURE, SOUND, VIDEO и другие загрузчики, задаются относительно папки модуля; поставляемые модули по соглашению хранят их в подпапках Textures, Sounds, Videos и Databases, а переводы кладут в папку lang.

Два вида скриптов живут в других местах:

- Фоны (фоны экранов, слои игрового процесса, толпа, анимации клира, кусудама) представляют собой файлы Script.lua в папке Graphics скина, в каталоге того экрана, который они украшают. См. раздел «Фоны» на странице [Модули и жизненный цикл](api/activities.md).
- Персонажи представляют собой папки в Global/Characters. Папка персонажа может содержать собственный Script.lua; без него игра использует встроенный скрипт персонажа. См. [Добавление персонажей](guides/characters.md).

## Script.lua определяет глобальные функции

Script.lua модуля определяет глобальные функции верхнего уровня с фиксированными именами, и игра читает каждую из них как глобальную переменную. Игра никогда не найдёт функцию, которую вы обернули в локальную таблицу и вернули, и никогда не вызовет функцию с опечаткой в имени (OnStart вместо onStart), потому что считает неопределённый обратный вызов пустой операцией и ничего не сообщает. Всё остальное в файле может быть локальным, а сам модуль можно разбить на несколько файлов, загружаемых через require.

demo3 — минимальная форма, которую стоит скопировать:

```lua
-- Modules/Stages/mystage/Script.lua
local text = nil
local textTex = nil

function onStart()          -- один раз при загрузке скина: загружайте ресурсы здесь
    text = TEXT:Create(16)
end

function activate()         -- при каждом входе в сцену
    textTex = text:GetText("Hello")
end

function update(timestamp)  -- каждый кадр: ввод и изменения состояния
    if INPUT:Pressed("Cancel") or INPUT:KeyboardPressed("Escape") then
        return Exit("title", nil)
    end
end

function draw()             -- каждый кадр: только отрисовка
    if textTex ~= nil then textTex:Draw(200, 200) end
end

function deactivate()       -- при выходе из сцены: остановите звуки, закройте базы данных
end

function onDestroy()        -- перед выгрузкой скина: освободите то, что создали
    if textTex ~= nil then textTex:Dispose() end
end
```

## Жизненный цикл сцены

- onStart(): игра вызывает его один раз после загрузки скина и снова после каждой перезагрузки скина, независимо от того, показана ли сцена на экране. Загружайте здесь текстуры, звуки и видео. Выполняется как корутина, поэтому долгую загрузку можно распределить по кадрам за полосой загрузки с помощью объекта LOADING.
- activate(): игра вызывает его при каждом входе в сцену. Сбрасывайте здесь состояние конкретного посещения, запускайте музыку и открывайте базы данных. Тоже выполняется как корутина и может использовать LOADING. Игра обновляет списки персонажей и пучичар (CHARACTERLIST, PUCHICHARALIST) непосредственно перед запуском activate, поэтому читайте их здесь; onStart выполняется до этого обновления.
- update(timestamp): игра вызывает его каждый кадр перед draw и передаёт игровые часы в миллисекундах. Обрабатывайте здесь ввод и меняйте состояние. После того как сцена вызвала Exit, игра перестаёт вызывать update и продолжает вызывать draw на протяжении затемнения.
- draw(): игра вызывает его каждый кадр. Только рисуйте и держите число выделений памяти на кадр низким.
- deactivate(): игра вызывает его при выходе из сцены. demo3 освобождает здесь свои базы данных; demo1 останавливает музыку и видео.
- afterSongEnum(): игра вызывает его при каждом завершении перечисления песен: при запуске и после мягкой или полной перезагрузки, даже если сцена не активна. Используйте его, если модуль зависит от списка песен.
- onDestroy(): игра вызывает его перед выгрузкой скина. demo1 освобождает здесь текстуру, видео, текстовую текстуру и звуки.
- reloadLanguage(lang): игра вызывает его при смене языка (см. раздел о локализации ниже).

При загрузке скина игра создаёт модули вид за видом: сначала Transitions, затем Stages, Activities и ROActivities. Внутри одного вида она сначала выполняет каждый Script.lua и только потом вызывает onStart. Поэтому, пока выполняется onStart сцены, Activity и ROActivity ещё не существуют; ищите их в activate.

Остальные виды используют вариации этого набора. У Activity и ROActivity те же обратные вызовы, но activate, deactivate, draw и update вызывает сцена-хост, и она же получает их возвращаемые значения. Фоны получают объект состояния в activate(state), update(timestamp, state) и draw(state) и могут определять обработчики событий, такие как clearIn, playEndAnime и kusuBroke. Переходы определяют fadeOut(t), loading(progress, elapsed) и fadeIn(t). Персонажи определяют собственный набор функций анимации и голоса. Страница [Модули и жизненный цикл](api/activities.md) перечисляет их все.

## Выбор вида модуля

- Сцена (Modules/Stages): полноценный экран, на который переключается игра. Она владеет кадром, обрабатывает ввод и покидает экран вызовом Exit. Используйте её для всего, что является отдельным экраном.
- Activity (Modules/Activities): подэкран, который сцена использует изнутри, например диалог. Это синглтон, который вы ищете через ACTIVITY:GetActivity(name); сцена-хост вызывает его Activate, Update, Draw и Deactivate. Используйте его для общих компонентов, которым разрешено изменять состояние игры.
- ROActivity (Modules/ROActivities): вариант Activity только для чтения, который вы ищете через ROACTIVITY:GetROActivity(name). Он получает CONFIG, DATABASE и GetSaveFile только для чтения и не имеет глобального объекта ACTIVITY. Используйте его для компонентов, которые только читают состояние, а это большинство переиспользуемого интерфейса. Движок размещает несколько собственных наложений как ROActivity с фиксированными именами (nameplate, modal, modicons, danplate, popup_menu, config_ui, song_enum); скин заменяет одно из них, поставляя папку с таким именем и сохраняя обратные вызовы, которые вызывает движок.
- Фон: Script.lua в папке Graphics, который рисует позади или поверх одного из экранов движка. Фоны получают те же глобальные объекты только для чтения, что и ROActivity.
- Переход (Modules/Transitions): затемнение, загрузка и появление, которые игра проигрывает между сценами. Сцена выбирает переход по имени в третьем аргументе Exit; игра откатывается к переходу с именем default, когда сцена не указала имя или такого имени не существует, и проигрывает переход с именем song_loading при входе в игровой процесс.
- Персонаж: см. [Добавление персонажей](guides/characters.md).

## Выход из сцены через Exit

Глобальный объект Exit есть только у сцен. Он принимает до трёх аргументов и допускает nil в любой позиции: цель ("title", "play", "stage" или "legacy"; nil означает "title"), имя целевой сцены, когда цель равна "stage" (или устаревший ключ, когда цель равна "legacy"), и имя модуля перехода. Поставляемые сцены пишут `return Exit(...)` внутри update, чтобы в этом кадре больше ничего не выполнялось.

```lua
-- из demo1/Script.lua, внутри update()
if INPUT:KeyboardPressed("S") == true then
    sounds.Skip:Play()
    return Exit("stage", "demo2")   -- переход в Modules/Stages/demo2
end
-- ...
return Exit("title", nil)           -- назад на титульный экран
```

## Песочница

Каждый Script.lua выполняется в ограниченном состоянии Lua:

- В os остаются только time, date и difftime. Песочница удаляет io, debug, loadfile и dofile, а import ничего не делает.
- package сводится к пользовательскому загрузчику: package.path и package.cpath пусты, а песочница заменяет стандартные искатели, поэтому поиск возможен только по путям ниже.
- require сначала ищет в папке самого модуля, затем в папке Modules/Lib скина и загружает первый найденный файл. Файл модуля и файл из Lib с одинаковым именем разрешаются в файл модуля. Точки в имени становятся разделителями пути, поэтому require("DBControllers.dbScores") и require("DBControllers/dbScores") загружают один и тот же DBControllers/dbScores.lua. Пути с символами не из ASCII работают.

```lua
-- из intro_nokon/Script.lua
local DBScores  = require("DBControllers/dbScores")  -- собственная подпапка модуля
local I18N      = require("i18n")                     -- Modules/Lib/i18n.lua
local Opening   = require("opening")                  -- папка модуля
local Dialogue  = require("nokon_dialogue")           -- папка модуля
```

## Модули только для чтения

Игра создаёт ROActivity и фоны с ограниченными глобальными объектами ещё до выполнения их Script.lua: CONFIG является представлением только для чтения, GetSaveFile(player) возвращает файл сохранения только для чтения, DATABASE открывает хранилища только для чтения, а ACTIVITY равен nil (используйте ROACTIVITY). Запись через любой из них выводит уведомление об ошибке в журнал, ничего не делает и не возбуждает ошибку Lua. Модуль, которому нужно изменять настройки, данные сохранения или базу данных, должен быть Activity или сценой.

## Локализация через lang/

Поставляемый скин переводит собственные строки каждого модуля общей библиотекой Modules/Lib/i18n.lua. Ключом служит английская строка в коде: модуль поставляет lang/ja.lua, который возвращает таблицу, сопоставляющую каждой английской строке её японский перевод, и библиотека ищет строки в этой таблице.

В библиотеке три функции:

- detect() читает текущий язык игры через глобальный объект LANG и загружает словарь для него. Если язык японский, она подключает lang/ja через require; путь разрешается внутри папки модуля, поэтому у каждого модуля свой словарь. Для любого другого языка она ничего не загружает. Пока вы её не вызвали, словарь не загружен и все строки остаются английскими.
- tr(s) возвращает перевод s из загруженного словаря либо саму s, если в словаре нет такой записи или словарь не загружен.
- trf(fmt, ...) так же переводит строку формата fmt, а затем форматирует её через string.format.

Вызывайте detect() в activate, а затем стройте текст с помощью tr и trf. activate выполняется при каждом входе в модуль, поэтому язык, который игрок сменил в настройках, вступает в силу при следующем посещении, и другой хук модулю не нужен. Ключи должны в точности совпадать с английским оригиналом, включая пунктуацию, пробелы и переносы строк, а перевод должен сохранять заполнители вроде %s или {Player 1 name} дословно.

```lua
-- Modules/Stages/mystage/lang/ja.lua
local T = {}
T["Nokon"] = "ノコン"
T["Alright, quiz time!"] = "さあ、クイズの時間である！"
return T
```

```lua
-- Modules/Stages/mystage/Script.lua
local I18N = require("i18n")
local title

function activate()
    I18N.detect()
    title = I18N.tr("Alright, quiz time!")
end
```

При смене языка игра также вызывает глобальную функцию reloadLanguage(lang) у каждого загруженного модуля. Она нужна только модулю, который остаётся на экране во время смены языка, например экрану с выбором языка; там вызовите detect() ещё раз и перестройте заранее отрисованный текст.

## На что обратить внимание

- Игра освобождает текстуры, звуки, видео и текстовые объекты, созданные модулем, когда уничтожает сам модуль, поэтому перезагрузка скина не приводит к их утечке. Освобождайте ресурсы, открываемые на каждое посещение, такие как базы данных, в deactivate, как делает demo3, и освобождайте всё созданное в onDestroy, как делает demo1.
- GetText кэширует по одной текстуре на каждую уникальную строку в своём текстовом объекте. Строка, меняющаяся каждый кадр, добавляет по текстуре каждый кадр, и игра постепенно замедляется. Рисуйте меняющиеся значения глифовым рендерером (TEXT:CreateGlyphCached) или сохраняйте одну текстуру, пока значение не изменится.
- LOADING работает только в обратных вызовах, выполняемых как корутины: onStart любого модуля и activate сцены. Вызов LOADING:Tick из activate Activity или из update или draw возбуждает ошибку Lua.
- onStart и afterSongEnum выполняются, пока модуль не показан на экране. Пишите их так, чтобы они работали и тогда, когда сцена не видна на экране.
