# Добавление наборов нот и оценок

Скин может предлагать несколько обликов нот и текстов оценки, и игрок выбирает один из них в настройках. Каждый облик представляет собой набор: пронумерованную папку в `Graphics/5_Game/` скина. Набор нот содержит ноты, дроби, шары, эффекты ударов и облачка шаров и дробей; набор оценок содержит тексты оценки. Это руководство объясняет папки, листы каждого набора, файл `Definition.json`, который описывает набор, и то, как игра восполняет то, чего в наборе нет.

## Прежде чем начать

- Собственный скин (см. [Добавление скинов и тем](skins.md)). В поставляемом скине `System/Open-World Memories/` есть четыре набора нот Тайко, один набор нот Бонго и четыре набора оценок, которые можно взять за образец.
- Графический редактор, который сохраняет PNG-файлы с прозрачностью.
- Размер ячейки ноты вашего скина: значение раскладки `Game_Notes_Size=` (`195,195` в поставляемом скине). Этот размер имеет каждая ячейка листов нот на этой странице, кроме ячеек гигантского листа.

## Шаг 1: создайте папки наборов

Игра ищет три папки в `Graphics/5_Game/` и считает каждую пронумерованную подпапку в них одним набором, по порядку номеров:

- `Notes Skin (Taiko)/`: наборы нот для игроков Тайко.
- `Notes Skin (Bongo)/`: наборы нот для игроков Бонго.
- `Judges Skin/`: наборы текстов оценки, их использует каждый игрок.

Набор `1` каждой папки служит набором по умолчанию и основой для остальных (шаг 7). Номер папки только задаёт порядок наборов; настройки показывают имя из `Definition.json`.

```
Graphics/5_Game/
  Notes Skin (Taiko)/
    1/                  <- облик по умолчанию, полный
      Definition.json
      Notes.png
      ...
    2/                  <- другой облик: только отличающиеся файлы
      Definition.json
      Notes.png
  Notes Skin (Bongo)/
    1/
  Judges Skin/
    1/
      Definition.json
      Judge.png
```

## Шаг 2: нарисуйте листы нот Тайко

В листе одна строка на каждый кадр анимации (число кадров задаёт шаг 5), а ячейки стоят рядом в порядке, указанном ниже.

| Файл | Содержимое |
| --- | --- |
| `HitCircle.png` | Круг удара, одна ячейка. |
| `Notes.png` | Дон, Ка, большой Дон, большой Ка, КаДон, ADLib. |
| `Rolls.png` | Голова, тело и хвост малой дроби, затем голова, тело и хвост большой дроби. Игра растягивает ячейку тела по длине дроби. |
| `Balloons.png` | Шар (2 ячейки в ширину), кусудама (2 ячейки в ширину), затем голова, тело и хвост фитильной дроби. Игроки Бонго тоже видят эти шары. |
| `ChipEffect.png` | Необязательно. Вспышка в том месте, куда приходит отбитая нота, с колонками `Notes.png`, одна строка. Без этого файла вспыхивает сама нота. |
| `Notes_Partner.png` | Необязательно. Партнёрский облик каждой колонки `Notes.png` (шаг 6). |
| `Notes_Giant.png` | Необязательно. Гигантские Дон, Ка, КаДон и ADLib (шаг 6). |
| `Preview.png` | Необязательно. Изображение, которое настройки показывают для набора. Без него они показывают `Notes.png`. |

Набор также содержит эффекты ударов и облачка шаров и дробей:

| Файл | Содержимое |
| --- | --- |
| `Hit/Explosion.png` | Всплеск над кругом удара, 7 квадратных кадров в строке: строка для Хорошо, строка для OK, затем по желанию строка для Хорошо и строка для OK на больших нотах. При 2 строках большие ноты используют первые две. |
| `Hit/Explosion_Big.png` | Дополнительный всплеск над большой нотой, одно изображение для обеих оценок. |
| `Hit/FireWorks.png` | Искры, которые оставляет за собой летящая большая нота. |
| `Hit/Bomb.png` | Взрыв отбитой бомбы или проваленной фитильной дроби, 7 кадров в одной строке. |
| `Hit/Great/`, `Hit/Great_Big/`, `Hit/Good/`, `Hit/Good_Big/` | Необязательные папки кадров (от `0.png` до `14.png`), которые игра рисует на дорожке при Хорошо (`Great`) или OK (`Good`) на малой или большой ноте. |
| `Kusudama/` | `Script.lua` кусудамы и её изображения, включая `Kusudama_Number.png`. |
| `Fuseroll/` | `Fuse.png`, облачко фитильной дроби, и `Number_Fuse.png`, его цифры. |
| `Breaking.png` | Изображения лопающегося облачка шара: 6 изображений одной высоты, одно над другим. |
| `Balloon.png` | Облачко шара. |
| `Roll.png` | Облачко счётчика дроби, его кадры анимации стоят рядом. |

## Шаг 3: нарисуйте набор нот Бонго

Набор Бонго содержит только то, что отличается для игроков Бонго:

| Файл | Содержимое |
| --- | --- |
| `Notes.png` | Красная, жёлтая, розовая, хлопок, ADLib. |
| `Rolls.png` | Красная, розовая и жёлтая дроби и дробь хлопков, каждая в виде головы, тела и хвоста. |
| `HitCircle.png` | Необязательно. Без него игроки Бонго видят круг удара набора Тайко. |
| `ChipEffect.png`, `Notes_Partner.png` | Необязательно, с колонками этого `Notes.png`. |
| `Notes_Giant.png` | Необязательно, с колонками этого `Notes.png`. |
| `Preview.png` | Необязательно. |

Шары, эффекты ударов и облачка всегда берутся из выбранного набора Тайко.

## Шаг 4: нарисуйте набор оценок

Набор оценок содержит `Judge.png`, 5 строк одной высоты: Хорошо, OK, Плохо, ADLib и Boom бомбы. Его `Definition.json` достаточно поля `Name`. Оставьте строку прозрачной, чтобы скрыть эту оценку; наборы "(Without Good)" поставляемого скина делают так со строкой Хорошо.

## Шаг 5: напишите Definition.json

`Definition.json` даёт набору имя и описывает его листы. Каждое поле необязательно; набор без этого файла показывает номер своей папки как имя и использует значения по умолчанию, указанные ниже.

```json
{
	"Name": { "strings": { "default": "Sky Spirits", "ja": "スカイスピリッツ" } },
	"Notes": {
		"Frames": 3,
		"Animation": [
			{ "FromCombo": 0, "Rows": [0] },
			{ "FromCombo": 50, "Rows": [1, 1, 0, 0], "RowsOnEntry": [0] },
			{ "FromCombo": 150, "Rows": [0, 1] },
			{ "FromCombo": 300, "Rows": [0, 2], "RowsOnEntry": [0, 1] }
		]
	},
	"Rolls": { "Frames": 3, "Animation": [] },
	"Balloons": { "Frames": 3, "Animation": [] },
	"FlyingNotesFrame": 1,
	"PartnerNotesScale": 1.4142,
	"GiantNotesScale": 2.0
}
```

| Поле | По умолчанию | Значение |
| --- | --- | --- |
| `Name` | номер папки | Имя в настройках, по одной строке на код языка, с `default` для всех остальных языков. |
| `Notes`, `Rolls`, `Balloons` | 1 кадр, без анимации | Число строк листа (`Frames`) и его анимация (`Animation`). `Notes` также задаёт строки `Notes_Partner.png` и `Notes_Giant.png`. |
| `FlyingNotesFrame` | `0` | Строка `Notes.png` для нот, которые после удара летят к шкале. |
| `PartnerNotesScale` | квадратный корень из 2 | Масштаб малой партнёрской ноты, когда в наборе нет `Notes_Partner.png` (шаг 6). |
| `GiantNotesScale` | `2` | Масштаб гигантской ноты, когда в наборе нет `Notes_Giant.png` (шаг 6). |

`Animation` содержит список уровней. Игра использует уровень с наибольшим `FromCombo`, которого достигло комбо игрока. В доле 4 шага, и `Rows` задаёт строку, которая рисуется на каждом шаге; более короткий список повторяется, поэтому `[0, 1]` чередуется на каждом шаге, а `[0]` стоит на месте. `RowsOnEntry` заменяет `Rows` примерно на две трети секунды после того, как комбо достигает этого уровня. Без уровней лист показывает свою первую строку. Таблица из примера повторяет анимацию, которую игра использовала всегда, а параметр «Режим просто» в настройках держит каждый лист на первой строке.

Два необязательных поля уточняют уровень. `FromComboByDifficulty` задаёт комбо уровня для некоторых сложностей, с ключами `Easy`, `Normal`, `Hard`, `Extreme` и `ExtraExtreme`; остальные сложности используют `FromCombo`, поэтому `"FromCombo": 100, "FromComboByDifficulty": { "Easy": 30 }` начинает уровень с 30 комбо на Easy и со 100 на остальных. Чарт Tower считается Normal на стороне Normal и Extreme на остальных сторонах, а Dan использует сложность песни, которая сейчас играет.

`RowsByNote` даёт некоторым нотам собственные `Rows`, с именами из таблицы ниже в качестве ключей; остальные ноты сохраняют `Rows`. В `Notes.png` запись `"Rows": [0, 2], "RowsByNote": { "BigDon": [1, 2] }` чередует строки 0 и 2 у всех нот, кроме большого Дона, у которого чередуются строки 1 и 2. Тело и хвост дроби следуют за её головой, а `RowsOnEntry` по-прежнему действует на все ноты.

| Лист | Имена нот |
| --- | --- |
| `Notes.png`, Тайко | `Don`, `Ka`, `BigDon`, `BigKa`, `KaDon`, `ADLib` |
| `Notes.png`, Бонго | `Red`, `Yellow`, `Pink`, `Clap`, `ADLib` |
| `Rolls.png`, Тайко | `Roll`, `BigRoll` |
| `Rolls.png`, Бонго | `RedRoll`, `PinkRoll`, `YellowRoll`, `ClapRoll` |
| `Balloons.png` | `Balloon`, `Kusudama`, `FuseRoll` |

## Шаг 6: партнёрские и гигантские ноты

Партнёрская нота в большинстве случаев сохраняет свой размер, но малые (малый Дон или Ка, ADLib, бомба, каждая нота Бонго) получают большой облик. Гигантская нота намного крупнее и медленно покачивается. У каждой есть свой необязательный лист:

- У `Notes_Partner.png` колонки `Notes.png` и столько же строк. Малая партнёрская нота использует ячейку своей колонки.
- У `Notes_Giant.png` столько же строк, сколько у `Notes.png`. В наборе Тайко его колонки: Дон, Ка, КаДон и ADLib, потому что гигантская нота выглядит большой независимо от своего размера: малый Дон и большой Дон оба используют ячейку Дон. В наборе Бонго его колонки совпадают с колонками `Notes.png`. Размер ячейки равен ширине листа, делённой на число колонок, поэтому гигантская ячейка может быть больше ячейки ноты.

Без этих листов игра строит облики из `Notes.png`:

| Нота | Партнёрская, без `Notes_Partner.png` | Гигантская, без `Notes_Giant.png` |
| --- | --- | --- |
| Малый Дон или Ка Тайко | Большой Дон или Ка | Большой Дон или Ка, умноженный на `GiantNotesScale` |
| Любая другая малая нота | Нота, умноженная на `PartnerNotesScale` | Нота, умноженная на `PartnerNotesScale` и `GiantNotesScale` |
| Большой Дон, большой Ка, КаДон | Без изменений | Нота, умноженная на `GiantNotesScale` |

Задавайте оба масштаба, даже когда в наборе есть оба листа: тогда скинер, который скопирует набор и удалит лист, получит разумный размер. Масштабированная нота представляет собой растянутое изображение и выглядит мягче, чем ячейка, нарисованная в нужном размере.

<div class="callout warn">Игра читает Notes_Partner.png, Notes_Giant.png и ChipEffect.png только из выбранного набора. Они должны соответствовать собственным нотам набора, поэтому копии из набора 1 никогда их не заменяют.</div>

## Шаг 7: пусть набор 1 восполнит остальное

Когда в выбранном наборе нет какого-то файла, игра берёт его из набора 1 той же папки. Поэтому набор может содержать только то, что он меняет: набор, который только очищает строку `Hit/Explosion.png`, содержит `Definition.json` и этот один файл. Правила:

- Игра проверяет каждый файл отдельно, в том числе внутри папок (`Hit/Great/3.png`). Исключение составляет кусудама: набор без собственной папки `Kusudama/` использует всю папку набора 1.
- Подстановка доходит только до набора 1. Набор, который меняет набор 3, должен содержать собственные копии листов набора 3.
- Игра никогда не берёт из набора 1 `Definition.json` и три листа из шага 6.
- Набор Бонго берёт недостающие файлы из набора Бонго 1.

## Шаг 8: выберите набор

Когда в одной из трёх папок скина есть хотя бы 2 набора, страница «Тема» в настройках первым показывает раздел «Скины нот» с одним выбором для этой папки и превью набора под ним. Игра сразу загружает выбранный набор и запоминает выбор для скина в `ThemeSettings.db3`. При единственном наборе выбор не появляется, и игра использует этот набор.

Lua-модуль читает файл выбранного набора через `THEME:GetNotesSkinFile(kind, file)` (см. [Игроки и профили](../api/players.md)). Поставляемый экран выбора песни использует его, чтобы рисовать тексты оценки в своём списке реплеев:

```lua
local file = THEME:GetNotesSkinFile("judges", "Judge.png")   -- "5_Game/Judges Skin/2/Judge.png" или ""
if file == "" then file = "5_Game/Judge.png" end              -- скин без наборов оценок
```

## Скины без наборов

Скин без папки `Notes Skin (Taiko)/` сохраняет файлы, которые у него были до появления наборов: `Notes.png` (круг удара, 4 ноты, дроби и шар), `Swap.png` (КаДон), `Adlib.png`, `Kusu.png`, `FuseRoll.png`, `ChipEffect.png`, папку `10_Effects/Hit/` и файлы шаров из `11_Balloon/`. Без папки `Notes Skin (Bongo)/` ноты и дроби Бонго берутся из `Notes_Konga.png`, а без папки `Judges Skin/` оценки берутся из `5_Game/Judge.png`. У этих файлов нет партнёрских и гигантских листов, поэтому партнёрские и гигантские ноты используют масштабированные облики из шага 6.

## Устранение неполадок и примечания

- Настройки не показывают выбор: в папке один набор, или папки наборов названы не числами.
- Набор показывает ноты другого набора: подстановка взяла файл из набора 1, потому что в наборе его нет, или имя файла отличается регистром букв в системе, чувствительной к регистру.
- Ноты показывают не тот кадр или обрезанное изображение: `Frames` не совпадает с высотой листа, делённой на высоту ячейки.
- Партнёрские или гигантские ноты скопированного набора выглядят как старые: копия сохранила `Notes_Partner.png` или `Notes_Giant.png` оригинала.
- Игроки Бонго не видят нот: `Notes.png` нет ни в выбранном наборе Бонго, ни в наборе Бонго 1.
