# Добавление скинов и тем

Скин — это папка в каталоге `System/` игры. Она поставляет графику, звуки, шрифты, значения раскладки, файлы локализации и Lua-модули, которые рисуют каждый экран. Это руководство объясняет, что делает папку скином, ключи `SkinConfig.ini`, структуру папок, дерево Lua-модулей и его жизненный цикл, а также то, как установить и выбрать скин. Сам Lua API (отрисовка, звук, ввод и так далее) описывает справочник API.

Скин также несёт Lua-модули, которые выполняют каждый экран. Игра загружает определённые модули по имени и переходит к определённым сценам, поэтому выбор скина показывает скин, собранный с нуля, но игра не может его запустить. Начинайте с копии поставляемого скина.

## Прежде чем начать

- Установленный OpenTaiko 0.6.1 с присутствующим поставляемым скином `System/Open-World Memories/`.
- Текстовый редактор для `SkinConfig.ini`, подключаемых файлов `*Config.ini` и Lua-модулей.
- Базовые знания Lua, если вы собираетесь менять поведение экранов. Чистая перерисовка (замена файлов PNG и OGG и правка значений `.ini`) Lua не требует.

## Шаг 1: разберитесь, что делает папку скином

При запуске игра перечисляет подпапки `System/`. Папка считается скином, только если внутри неё существует `Graphics/1_Title/Background.png`; любую другую папку игра пропускает. Если папка выбранного скина отсутствует, игра откатывается к `System/Default/`, затем к первому подходящему скину в алфавитном порядке, затем к самой `System/`.

Эта проверка лишь добавляет папку в список. Шаг 8 называет модули, которые также должны существовать, чтобы скин работал.

```
System/
  Open-World Memories/         <- поставляемый скин
  My New Skin/                 <- ваш скин
    Graphics/
      1_Title/
        Background.png          <- обязателен, чтобы папка попала в список
    SkinConfig.ini
```

## Шаг 2: скопируйте поставляемый скин

Скопируйте `System/Open-World Memories/` в новую соседнюю папку, например `System/My New Skin/`. Копия содержит всё, что нужно игре: `Graphics/`, `Sounds/`, `Fonts/`, `Locales/`, `Modules/`, `ThemeSettings.json`, `SkinConfig.ini` и подключаемые им файлы `*Config.ini`. Имя папки — это идентичность скина (игра записывает его как выбранный скин, и выбор скина его показывает), поэтому используйте имя, безопасное для файловой системы. Затем отредактируйте `SkinConfig.ini`, чтобы метаданные описывали ваш скин.

## Шаг 3: отредактируйте SkinConfig.ini

`SkinConfig.ini` — файл `Key=Value`, по одной настройке на строку. Парсер обрезает начальные пробелы и табуляции, считает строки, начинающиеся с `;`, комментариями и читает строку, только если она содержит ровно один `=`. Ключи сопоставляются точно, а неизвестный ключ парсер игнорирует, не сообщая об ошибке. Ключи уровня скина:

- `Name=`: отображаемое имя. Только метаданные; скин выбирает имя папки.
- `Version=`, `Creator=`: произвольные строки (по умолчанию `Unknown`). Игра их не проверяет.
- `DefaultLocale=`: идентификатор локали, который игра использует, когда у активного языка игры нет файла в `Locales/` (по умолчанию `en`).
- `Resolution=W,H`: разрешение, для которого вы задаёте значения раскладки (по умолчанию `1280,720`). Поставляемый скин использует `1920,1080`.
- `Resolutions=`: доступные для выбора множители масштаба рендера (шаг 4).
- `AIBattleCharacter=`: папка персонажа, используемого для противника-ИИ (шаг 5).
- `FontName<LANG>=` и `BoxFontName<LANG>=`: файл шрифта для каждого языка игры, где `<LANG>` — код языка в верхнем регистре (`EN`, `JA`, `FR`, `ES`, `NL`, `DE`, `RU`, `KO`, `ZH`). Путь задаётся относительно корня скина (абсолютный путь тоже работает), и файл должен существовать, иначе парсер отбрасывает ключ.

Все остальные ключи (`Game_*`, `Result_*`, `Title_*` и так далее) — значения раскладки экранов. Их читает тот же парсер, поэтому они могут находиться в подключаемых файлах из шага 6.

```ini
;Сведения о скине
Name=My New Skin
DefaultLocale=en
Version=1.0.0
Creator=Your Name
Resolution=1920,1080
;Доступные множители масштаба рендера (<=1; десятичная дробь или дробь a/b, через запятую). 1 доступен всегда и используется по умолчанию.
Resolutions=1,2/3,1/3
;Папка персонажа, используемого для слота битвы с ИИ.
AIBattleCharacter=10v2 - AItritus
FontNameEN=Fonts/MPLUSRounded1c-Medium.ttf
FontNameJA=Fonts/MPLUSRounded1c-Medium.ttf
BoxFontNameEN=Fonts/MPLUSRounded1c-Regular.ttf
BoxFontNameJA=Fonts/MPLUSRounded1c-Regular.ttf
```

## Шаг 4: параметр Resolutions

`Resolutions=` — список множителей масштаба рендера через запятую, которые предлагает меню настроек. Игра рендерит в `Resolution`, умноженное на выбранный множитель, и масштабирует результат под окно; размер окна не меняется. Каждый элемент — десятичная дробь (`0.5`) или обыкновенная дробь (`2/3`). Парсер отбрасывает элементы вне диапазона 0 < значение <= 1, неразбираемые элементы и дубликаты, добавляет `1`, если он отсутствует, и сортирует список так, чтобы `1` шёл первым. Разделителем должна быть запятая, потому что точка с запятой начинает строку комментария. Меню настроек показывает каждую запись с размером в пикселях, например `2/3 (1280x720)` для скина 1920x1080.

```ini
Resolution=1920,1080
Resolutions=1,2/3,1/3
; даёт следующие варианты:
;   1     -> 1920x1080  (по умолчанию)
;   2/3   -> 1280x720
;   1/3   -> 640x360
```

## Шаг 5: параметр AIBattleCharacter

`AIBattleCharacter=` называет папку в `Global/Characters/`, которую игра использует для противника-ИИ в режиме битвы с ИИ. По умолчанию это `10v2 - AItritus`. Указанная папка должна существовать.

```ini
;Папка персонажа, используемого для слота битвы с ИИ.
AIBattleCharacter=10v2 - AItritus
```

## Шаг 6: разделите конфигурацию с помощью #include

Когда парсер встречает строку вида `#include SomeFile.ini`, он читает указанный файл на этом месте, рекурсивно. Путь задаётся относительно корня скина. Поставляемый `SkinConfig.ini` содержит только метаданные и ключи шрифтов, а затем подключает по одному файлу на экран. Сохраняйте эти строки при копировании скина и редактируйте отдельные файлы `*Config.ini`, чтобы перенастроить экран.

```
; конец SkinConfig.ini (поставляемый скин, по порядку)
#include OtherConfig.ini
#include TitleConfig.ini
#include ConfigConfig.ini
#include SongSelectConfig.ini
#include HeyaConfig.ini
#include SongLoadingConfig.ini
#include GameConfig.ini
#include ModIconsConfig.ini
#include NameplateConfig.ini
#include AIResultConfig.ini
#include ResultConfig.ini
#include DaniSelectConfig.ini
#include DanResultConfig.ini
#include TowerResultConfig.ini
#include TowerSelectConfig.ini
#include OnlineLoungeConfig.ini
#include OpenEncyclopediaConfig.ini
#include ModalConfig.ini
#include Game4PConfig.ini
#include Result4PConfig.ini
#include Modal4PConfig.ini
```

## Шаг 7: изучите структуру папки скина

Если взять поставляемый скин за образец, корень скина содержит:

- `Graphics/`: изображения, сгруппированные в пронумерованные папки по экранам (`0_Startup`, `1_Title`, `2_Config`, `3_DaniSelect`, `5_Game`, `6_Result`, `7_DanResult`, `7_Exit`, `8_TowerResult`, `10_Heya`, `12_OnlineLounge`, `13_TowerSelect`, `15_OpenEncyclopedia`), плюс несколько общих изображений на верхнем уровне. Анимированные фоны — файлы `Script.lua`, которые лежат рядом с изображениями папки, к которой они относятся (например `Graphics/0_Startup/Script.lua` и папки в `Graphics/5_Game/5_Background/`).
- `Sounds/`: системные звуки и BGM, которые игра загружает по фиксированным именам файлов, например `Sounds/Move.ogg`, `Sounds/Decide.ogg`, `Sounds/Cancel.ogg`, `Sounds/BGM/Title.ogg`, `Sounds/BGM/SongSelect.ogg`, `Sounds/BGM/Result.ogg`. Если файл отсутствует, этот звук не проигрывается.
- `Fonts/`: файлы `.ttf`, на которые ссылаются ключи `FontName`.
- `Locales/`: по одному JSON-файлу на язык (`en.json`, `ja.json`, ...) вида `{ "Entries": { "KEY": "text" } }`. Эти строки подписывают собственные настройки скина, и Lua читает их через `THEME:GetSkinString(key)`. Когда ключ отсутствует в активном языке, игра ищет его в файле `DefaultLocale`.
- `Modules/`: дерево Lua-модулей (шаг 8).
- `ThemeSettings.json`: массив настроек, которые экран параметров показывает в разделе «Theme Settings». Каждая запись содержит `id`, `type` (`bool`, `int`, `double`, `string` или `enum`), `scope` (`global`, по умолчанию, или `save` для отдельного значения на каждый файл сохранения), локализованные `label` и `description`, `default`, а также `min`/`max` или `options` в зависимости от типа.
- `SkinConfig.ini` и подключаемые файлы `*Config.ini`.
- `README.txt`, `LICENSE.md`, `Licenses/`: файлы с указанием авторства. Игра их не читает.

```
My New Skin/
  SkinConfig.ini
  ThemeSettings.json
  Graphics/           изображения по экранам; в некоторых папках есть фоновый Script.lua
  Sounds/             системные звуки .ogg с фиксированными именами и BGM/
  Fonts/              файлы .ttf, названные в ключах FontName
  Locales/            en.json, ja.json, ... ({ "Entries": { ... } })
  Modules/            дерево Lua-модулей (шаг 8)
  <screen>Config.ini  файлы раскладки, подключаемые через #include
```

## Шаг 8: дерево Modules и модули, которые требует игра

При загрузке скина игра сканирует четыре подпапки `Modules/` и считает каждую непосредственную подпапку внутри них одним модулем с точкой входа `Script.lua`:

- `Modules/Transitions/`: переходы, которые проигрываются между сценами. Игра загружает их первыми, чтобы они были готовы к первому переключению сцен.
- `Modules/Stages/`: полноценные экраны. В сцену вы входите через `Exit("stage", "<folder name>")`.
- `Modules/Activities/`: переиспользуемые подэкраны, накладываемые на сцену (например `confirm_dialog`, `mod_select_dialog`, `song_select_core`).
- `Modules/ROActivities/`: наложения только для чтения, которыми игра управляет напрямую.

Игра не сканирует `Modules/Lib/`. Файлы оттуда вы загружаете через `require`: путь поиска модуля — его собственная папка, затем `Modules/Lib/`, поэтому `require("dialogue")` разрешается в `Modules/Lib/dialogue.lua`. Сцены и активности вы также можете размещать в `Global/Stages/` и `Global/Activities/` в папке установки игры; игра загружает их для каждого скина.

Внутри каждой категории игра сначала создаёт каждый модуль, а затем выполняет `onStart` у каждого, в порядке Transitions, Stages, Activities, ROActivities.

Игра ищет следующие модули по имени, и поставляемый скин предоставляет их все:

- Сцены `_boot` и `_title`. Игра останавливается с ошибкой, если любая из них отсутствует.
- ROActivity `modal`, `config_ui`, `nameplate`, `popup_menu`, `modicons`, `song_enum` и `danplate`.
- Переходы `default` и `song_loading`. `song_loading` проигрывается, пока игра загружает песню; игра использует `default`, когда `Exit` не называет переход или называет несуществующий. Скин вообще без модулей переходов откатывается к простому затемнению в чёрный.

Сохраняйте все их при сборке скина; добавляйте собственные модули рядом с ними.

```
Modules/
  Transitions/   <name>/Script.lua   (загружаются первыми; "default" и "song_loading" использует игра)
  Stages/        <name>/Script.lua   ("_boot" и "_title" обязательны)
  Activities/    <name>/Script.lua
  ROActivities/  <name>/Script.lua   (modal, config_ui, nameplate, popup_menu, modicons, song_enum, danplate обязательны)
  Lib/           общие .lua-файлы, доступные через require, не сканируются
```

## Шаг 9: Script.lua сцены и его жизненный цикл

`Script.lua` выполняется один раз, когда игра создаёт модуль, и глобальные объекты движка (`TEXTURE`, `SOUND`, `INPUT`, `CONFIG`, `THEME` и остальные) уже определены. Затем игра ищет глобальные функции по имени и вызывает их. Для сцены:

- `onStart()`: один раз, при загрузке скина. Выполняется как корутина, поэтому тяжёлая загрузка может вызывать `coroutine.yield()` или помощники `LOADING`, чтобы распределить работу по кадрам за полосой загрузки.
- `activate()`: при каждом входе игры в сцену. Тоже корутина. Игра обновляет глобальные объекты `CHARACTERLIST` и `PUCHICHARALIST` непосредственно перед его запуском, поэтому всё, что от них зависит, стройте здесь; в `onStart` они ещё пусты.
- `update(timestamp)`: каждый кадр. Верните `Exit(target, name, transition)`, чтобы покинуть сцену. `target` — это `"title"`, `"play"`, `"stage"` (с `name` = папка сцены) или `"legacy"` (с `name` = `heya`, `config`, `exit` или `onlinelounge`); `transition` — папка в `Modules/Transitions/`, по умолчанию `default`.
- `draw()`: каждый кадр.
- `deactivate()`: когда игра покидает сцену.
- `afterSongEnum()`: когда список песен закончил перечисление.
- `onDestroy()`: когда игра выгружает скин.

Все они необязательны; функцию, которую вы не определили, игра пропускает. Activity, ROActivity и переходы следуют той же схеме с собственными наборами функций.

```lua
-- Modules/Stages/my_stage/Script.lua
function onStart()
  -- однократная настройка; при тяжёлой загрузке можно вызывать coroutine.yield()
end

function activate()
  -- выполняется при каждом входе в сцену
end

function update(ts)
  if INPUT:Pressed("Cancel") then
    return Exit("stage", "_title")   -- покинуть эту сцену
  end
  return nil
end

function draw()
  -- покадровая отрисовка
end

function deactivate() end
function afterSongEnum() end
function onDestroy() end
```

## Шаг 10: локализуйте модуль через lang/

Модуль может хранить собственные переводы в подпапке `lang/` рядом со `Script.lua`. Поскольку собственная папка модуля находится в его пути `require`, `require("lang.ja")` разрешается в `lang/ja.lua`. Поставляемый скин делает так для своих крупных сцен (например `Modules/Stages/myroom/lang/ja.lua` и `Modules/Stages/intro_nokon/lang/ja.lua`) через помощник `Modules/Lib/i18n.lua`. Это отдельный механизм, не связанный с общескиновой папкой `Locales/` из шага 7.

```
Modules/Stages/my_stage/
  Script.lua
  lang/
    ja.lua        -- require("lang.ja")
```

## Шаг 11: установите и выберите скин

Поместите папку в `System/`. Откройте настройки, перейдите в раздел «Appearance» и выберите скин в параметре «Skin»; выбор перечисляет каждый подходящий скин по имени папки и показывает его `Graphics/1_Title/Background.png` как миниатюру. Когда вы меняете скин, игра выгружает текущий, загружает новый и перезагружает все его Lua-модули за полосой загрузки.

Игра записывает выбор в `Config.ini` как `SkinPath=` относительно `System/`. Она записывает голое имя папки (например `SkinPath=My New Skin\` в Windows) и также принимает форму `./My New Skin/`, показанную в комментарии файла.

```ini
; В Config.ini (записывается при выборе скина в игре):
; Путь к папке скина относительно System/
SkinPath=My New Skin\
```

## Устранение неполадок и примечания

- Выбор скина не показывает скин: отсутствует `Graphics/1_Title/Background.png` или папка лежит не непосредственно в `System/`.
- Игра выдаёт ошибку сразу после того, как вы выбрали скин: отсутствует обязательный модуль (шаг 8) или один из них возбудил ошибку Lua. Проверяйте скин, переключаясь на него.
- Ключ `SkinConfig.ini` не действует: ключ написан с ошибкой, строка содержит больше одного `=` или значение не удалось разобрать. Неизвестные ключи парсер игнорирует, не сообщая о них.
- `Resolutions=` показывает только `1`: в списке использованы точки с запятой (маркер комментария) или все значения оказались вне диапазона 0 < значение <= 1.
- Ключ шрифта не действует: путь к файлу не существует относительно корня скина.
- `CHARACTERLIST` или `PUCHICHARALIST` пусты в `onStart`: игра заполняет их после создания модулей. Используйте их из `activate`.
- Переименование папки скина меняет его идентичность; `SkinPath` в `Config.ini` должен указывать на новое имя.
- `Name=`, `Version=` и `Creator=` носят только информационный характер. Игра не выполняет по ним проверку совместимости.
