# Shop

Логика магазина за монеты: каталог, ассортимент дня, обновления ассортимента, цены, покупки и то, что они дают. Модули `Shop` ничего не рисуют. Скин рисует поверх них собственный магазин и выбирает собственные переходы; все скины продают одни и те же товары по одним и тем же правилам, а покупки попадают в файл сохранения. Сцена `coin_shop` в Open-World Memories (журнал и его продавец) — один из таких клиентов.

## Модули

| Модуль | Что содержит |
| --- | --- |
| `Shop.Daily` | Магазин дня одного сохранения: розыгрыш, запас, распроданные слоты, обновления и покупки, сохраняемые от одного посещения до следующего. |
| `Shop.Catalog` | Товары: таблица `itempool` из `Items.db3` рядом с модулем и то, что даёт покупка каждого типа. |
| `Shop.Seasonal` | Избранные товары, которые в заданные даты занимают большой слот. |
| `Shop.Popup` | Необязательное всплывающее окно покупки через ROActivity `modal`, для скина, которому оно нужно. |
| `Shop.Texts` | Собственные строки модулей (`lang/<code>/shop.json`), включая названия товаров. |

## Shop.Daily

Каждый день по японскому времени (JST) магазин разыгрывает большой (избранный) слот из строк `major` и четыре обычных слота из строк `regular`, с весами `PoolSize`; если большой розыгрыш выпадает на строку `empty`, в этот день вместо этого шесть обычных слотов. Сезонная запись может занять большой слот. Обновление стоит 10 монет, удваиваясь с каждым обновлением за день, и пополняет запас всех слотов.

| Функция | Описание |
| --- | --- |
| `Daily.open(index, opts?)  -> shop` | Сегодняшний магазин для слота сохранения `index`: загружается, если сегодня он уже разыгран, иначе разыгрывается и сохраняется. `opts.store` называет локальное хранилище (`"shop_state"`), `opts.seasonal` — избранные записи (`Shop.Seasonal`). |
| `shop.big`, `shop.normals[1..6]` | Товары: строки каталога плюс `LocalizedName`, `Stock` и `SoldOut`; nil для пустого слота. |
| `shop:item(slot)  -> item` | Слот от 1 до 6 или `Daily.SLOT_BIG`. |
| `shop:refusal(slot, qty?)  -> string or nil` | Почему слот сейчас нельзя купить: `"none"`, `"soldout"`, `"poor"`. |
| `shop:buy(slot, qty?)  -> true, or false and a reason` | Покупает `qty` единиц (не больше запаса): выдаёт их, списывает цену, уменьшает запас и сохраняет. |
| `shop:reroll()  -> true, or false and "poor"` | Списывает цену обновления и разыгрывает новый запас. |
| `shop:rerollPrice()  -> number` | Цена следующего обновления. |
| `shop:close()` | Освобождает хранилище; вызывайте при закрытии экрана. |

Состояние хранится для каждого файла сохранения (по его `SaveUID`) в [локальном хранилище DATABASE](../api/data.md) вызывающей сцены: день, обновления, маска распроданных слотов, а также код товара и запас каждого слота. Поэтому сцены магазина двух скинов ведут раздельный ежедневный запас, а купленное у них общее.

## Shop.Catalog

Строка `itempool`:

| Столбец | Описание |
| --- | --- |
| `Code` | Уникальный код: `furn_<id>` для мебели Моей комнаты, `vault_key_*`, `nameplate_<n>`, ... |
| `Type` | Что даёт покупка: `nameplate` (`RefInt` — id таблички имени), `triggerable` (устанавливает триггер `RefText`), `counterable` (увеличивает счётчик `RefText` на количество), `empty` (большой слот в этот день пуст). |
| `Price`, `Name` | Цена в монетах и JSON-название `LANG`, которое используется, если у модуля нет строки для этого кода. |
| `Slot`, `PoolSize` | `regular` или `major`; вес строки в её пуле. |
| `Condition` | Триггер, который должен быть установлен, чтобы строка предлагалась. |
| `StockMin`, `StockMax` | Запас в диапазоне, покупаемый поштучно, если `StockMax` больше 0 (краски, покрытия пола). |
| `OneTime` | 1: покупается один раз за всё время и больше никогда не предлагается. |

| Функция | Описание |
| --- | --- |
| `Catalog.pools()  -> { normal, big }`, `Catalog.rows(slot)`, `Catalog.find(code)` | Строки, прочитанные один раз. |
| `Catalog.name(item)  -> string` | Название товара: строка модуля для этого кода, иначе `Name` строки. |
| `Catalog.grant(save, item, qty)` | Выдаёт покупку по её типу (`Catalog.GRANTS`, которую скин может дополнить своими типами). |
| `Catalog.isOwned(item, save)`, `Catalog.isIncluded(item, save)` | Есть ли в сохранении уникальный товар; может ли строка быть разыграна для него. |
| `Catalog.furnitureId(code)  -> string` | Id мебели Моей комнаты для кода `furn_<id>`, иначе nil. |

## Shop.Seasonal и Shop.Popup

`Shop.Seasonal` — это список записей [альманаха](calendar.md) `{ code, when, priority, sticky }`, где `code` — код товара: пока запись совпадает, а товара в сохранении нет, он занимает большой слот. Скин может передать в `Daily.open` собственный список.

`Shop.Popup.show(item, qty, picture?)` проигрывает всплывающее окно покупки через ROActivity `modal` (`picture` — имя общей текстуры; для мебели по умолчанию `myroom_thumb_<id>`); `Popup.update()` возвращает true, пока окно идёт, затем `Popup.draw()` и `Popup.stop()`.

## Ключи сохранения

Покупка записывается в сохранение покупателя:

| Ключ | Тип | Содержимое |
| --- | --- | --- |
| `.myroom_<id>` | счётчик | Купленная мебель (строки `counterable`), передаваемая в Мою комнату при её следующем посещении. |
| `.vault_key_count_<key>` | счётчик | Купленные ключи хранилища. |
| `<RefText>` | триггер | Куплена строка `triggerable`. |
| `<RefText>_owned` | триггер | Куплена разовая строка: она больше никогда не предлагается. |
| `.almanac_<code>` | триггер | Сезонная запись sticky совпала для этого сохранения. |

Таблички имени и монеты проходят через собственные методы сохранения (`UnlockNameplate`, `SpendCoins`).

```lua
local Daily = require("Shop.Daily")
local shop

function activate()
    shop = Daily.open(slot)
end

local function buy(i)
    local ok, why = shop:buy(i, 1)
    if not ok then showRefusal(why) end
end

function deactivate()
    shop:close()
end
```
